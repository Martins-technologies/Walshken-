# Part D review

Scope: private PDF, DOCX, XLSX and image upload, content previews, versioned replacement, metadata editing, categories, folders, internal forwarding, authenticated external recipients, server-side access controls, revocation and append-only audit.

The existing review branch enables WALSHKEN_DOCUMENTS_ENABLED=1 and reuses its protected Preview configuration without exporting encryption keys. Production stays on the current Part B/C release. The new doc_* tables are additive; only the existing review login receives their server-side grants. The production login does not inherit that review login. The old document endpoints are disabled in the review build to prevent bypasses. Files live in a separate private review bucket, using the existing S3 connection server-side, or dedicated document credentials configured in Integrations. Disabling an explicitly configured document integration never falls back to another connection.

All nine permissions apply at organization, department, group, ancestor-folder and individual-document levels. Matching explicit denies take precedence over allows. A Super Admin can administer the registry but cannot open a globally revoked or deleted file. Upload gives the uploader view/edit rights only; download, print, forwarding and external sharing require separate grants. Employees cannot use broad organization policies to access guest content: external recipients require explicit individual sharing.

Forwarding grants view only, checks the sender's current forward permission again on every recipient open, and cannot override a recipient denial. External forwarding additionally requires the external-sharing permission and an active guest account; links always require sign-in and MFA. No anonymous or public document links exist.

Opening creates a two-minute token bound to the current session, employee, version and purpose. Every preview page, original download and print request rechecks current permissions, account/session status, folder revocation and source-forwarding access. Object keys and storage credentials never reach the browser. Access can be revoked for a document, folder or recipient immediately for future requests. Preview content uses no-store responses and server-generated page images; PDFs are never sent to a view-only user.

Editing means metadata updates and versioned file replacement, with optimistic version checks; this does not provide a collaborative Office editor. Content previews may differ from Office's original layout. Supported file formats and the 3 MB limit are shown before upload. Password-protected, macro-enabled, malformed or oversized content is rejected with a clear error. Office archive limits prevent decompression bombs; external references, embedded active objects and macros are rejected. Excel formulas are not executed.

Watermarks identify the employee and time and are rendered into preview/print page images on the server. Original downloads are explicitly original files. Revocation cannot recall data already delivered. Browser restrictions cannot fully prevent screenshots, photography or information copying. Stronger data-loss protection may require managed devices.

Tests must cover format rendering, permissions at every level, deny precedence, cross-organization IDs, MFA/session expiration, version conflict, forwarding/revocation chains, guest restrictions, no raw original access, watermarking and audit actions. Live preview checks must verify actual private storage writes, denied public reads and authorized proxy reads. Temporary test data must be removed.
