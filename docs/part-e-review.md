# Part E task management

Implement the existing canonical task system with assignment, department/division snapshots, authorized project/client references, progress, immutable review decisions, notes, private supporting files, linked document permissions, manual time entries and persistent task timers. Every task action rechecks the current employee scope; assignment history does not preserve a manager's former access. Employees cannot approve their own work or set Completed directly. Submission locks work changes until approval or return; managers can reopen a closed task with a recorded reason.

The daily dashboard separates My tasks from a scoped Team view and shows today, overdue, upcoming deadlines, completed and pending-review tasks, estimated/actual hours and a real running-timer status. Time uses UTC timestamps with assignment time zones for day/deadline calculations. One running timer per employee is enforced in the database and caps at twelve hours. Manual log changes and task assignment changes are recorded. Active timers stop when work is submitted, paused, cancelled or reassigned.

Related library documents require current Part D view permission for the linking employee and the assignee; opening still uses the secure Part D endpoint and rechecks its ACL. Task supporting files are isolated in a separate private task bucket. They have task-scoped, session-bound two-minute raster previews, with employee identification watermarks and fresh task access checks per page. They do not create public URLs or original-download/external-sharing paths. File validation reuses Part D's PDF/DOCX/XLSX/image validators (3 MB, 200 pages). Deleting an attachment revokes access immediately and attempts object removal; failed removals remain queued for retry.

Database plan: additive task/notification columns, eight workflow tables, Preview-only runtime grants and two restrictive production RLS policies that exclude newly tagged Preview task/notification rows. Existing rows default to production and remain unchanged. No employee-wide permission grants, new accounts or production deployment. The existing protected Vercel review configuration is reused without exporting keys. A separate private `walshken-task-files-review` bucket uses the current encrypted S3 connection on the server.

An isolated five-minute Supabase Cron job performs Preview-only overdue reminders and timer expiry without paid external APIs. Overdue alerts go to the assignee and currently authorized managers once per recipient, task, due date and local day. Notifications are persisted and link to the task. The job does not process production tasks or call the production deployment.

Validation covers every task field and dashboard category, role/employee/department/division scope, project authorization, date/time zones, optimistic conflicts, timers/manual logs, submission/review/reopen transitions, comments, linked-document ACL revocation, private supporting files, overdue deduplication and Preview isolation. No sample task data is deployed. Production merging waits for the owner's explicit approval after manual testing.
