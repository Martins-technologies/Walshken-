# Validated payroll calculator contract

The optional calculator is an actual authenticated HTTPS adapter, not a preset connection to an unidentified payroll company. Native Alberta/CAD 2026 calculations do not use this API. Other jurisdictions, future tax years and special cases must use an independently validated implementation of this contract. Add its public hostname to WALSHKEN_PAYROLL_ALLOWED_HOSTS and configure the endpoint, provider name, API key and response-signing secret in Admin Integrations. Credentials remain encrypted server-side. No payroll data is sent until the administrator enables the connection and chooses it in the employee policy.

GET endpoint: authenticate the Bearer API key and return `protocol: "walshken-payroll-v1"`, `jurisdictions: ["CA-QC", ...]`, and supported numeric `taxYears`.

POST endpoint: authenticated JSON contains `protocol`, unique `requestId`, canonical payroll `inputHash`, `sentAt`, and `input`. Input includes payment date, jurisdiction, currency and minor-unit precision, employee classification, earnings with taxable/pensionable/insurable flags, approved deductions, YTD balances and verified tax elections. Implement the applicable calculation with maintained government rules or a validated payroll-service integration.

Return the same protocol, requestId and inputHash, `validated: true`, and `result`. Result fields: `engine`, `version`, `taxYear`, official `source`, unique calculation `reference`, `lines: [{code,label,employee,employer}]`, taxable/pensionable/insurable amounts, bonus/enhanced-bonus/bonus-CPP/bonus-EI amounts and annual taxable value. Monetary values are integer minor units in the input currency. Deduction codes distinguish FED, province-specific income tax, CPP/CPP2, QPP, EI and QPIP. Québec responses must explicitly identify QPP and QPIP, even for documented exemptions. Employer contributions are separate from employee deductions.

Sign the exact UTF-8 response body using HMAC-SHA256 and the configured signing secret. Send the lowercase hexadecimal signature in `X-Payroll-Signature`. The portal rejects mismatched input hashes, duplicate/stale request identities, unsigned responses, unsupported currencies/years, negative deductions and incomplete results. A successful connection check is not a certification of the provider's mathematics; employer payroll review and independent provider validation remain required.
